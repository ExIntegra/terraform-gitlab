# Terraform Lab: управление GitLab

Учебный проект для автоматизации настройки GitLab с помощью Terraform и провайдера [`gitlabhq/gitlab`](https://registry.terraform.io/providers/gitlabhq/gitlab/18.8.2/docs).

Конфигурация создаёт подгруппу и проект, назначает участникам роли, настраивает защиту основной ветки и добавляет переменную CI/CD. Родительская группа и учётные записи пользователей должны существовать заранее.

## Что настраивается

| Объект | Настройка |
| --- | --- |
| Родительская группа | Поиск существующей группы `it-akron` через `data` |
| Подгруппа | Создание `the_best_team` внутри родительской группы |
| Руководитель команды | Добавление пользователя `ChefIvan` с ролью `Maintainer` |
| Участники команды | Добавление пользователей `Maks`, `Gleb`, `Daniil` с ролью `Developer` через `for_each` |
| Проект | Создание `the_best_project` в подгруппе с начальным README и основной веткой `main` |
| Слияние изменений | Метод `merge` |
| Защита `main` | Прямой push запрещён, слияние разрешено роли `Maintainer` и выше, force push запрещён |
| CI/CD-переменная | Создание `MY_SECRET_VARIABLE` с флагами `protected`, `masked`, `hidden` |

Участники родительской группы могут наследовать доступ к подгруппе и проекту. Указанные назначения не отменяют унаследованные права.

## Структура репозитория

| Файл | Назначение |
| --- | --- |
| `main.tf` | Требования к версиям, настройка провайдера, входная переменная, источники данных и ресурсы |
| `.terraform.lock.hcl` | Выбранная версия провайдера и контрольные суммы пакетов |
| `.gitignore` | Исключение локальных файлов Terraform, state, файлов переменных и планов с расширением `.tfplan` |
| `README.md` | Описание проекта и порядок запуска |

## Требования

- Terraform **1.12.2**: в `required_version` закреплена точная версия.
- Git и доступ к API целевого GitLab.
- Существующая родительская группа и учётные записи участников.
- Personal Access Token с областью доступа `api` от пользователя с достаточными правами. Для этой лабораторной работы можно использовать владельца родительской группы; права администратора всего GitLab не обязательны.
- Версия GitLab, поддерживающая скрытые CI/CD-переменные. Возможность `hidden` появилась в GitLab 17.4.

## Подготовка

### 1. Клонирование

```bash
git clone https://github.com/ExIntegra/terraform-lab.git
cd terraform-lab
```

### 2. Настройка под своё окружение

В `main.tf` замените:

- `it-akron` на полный путь своей родительской группы;
- `ChefIvan` на username руководителя команды;
- `Maks`, `Gleb`, `Daniil` на username участников;
- имена, пути и описания создаваемых подгруппы и проекта при необходимости.

Для собственного сервера GitLab укажите адрес API. Пример для Bash:

```bash
export GITLAB_BASE_URL="https://gitlab.example.com/api/v4/"
```

Замените домен на свой. Завершающий `/` обязателен. Без переопределения адреса провайдер обращается к GitLab.com.

### 3. Передача токена

В конфигурации токен передаётся через входную переменную `admin_token`. Пример для Bash с вводом без отображения символов:

```bash
read -rsp "GitLab PAT: " TF_VAR_admin_token
echo
export TF_VAR_admin_token
```

В конце работы удалите переменную из текущего сеанса:

```bash
unset TF_VAR_admin_token
```

## Запуск

В текущей конфигурации `main.tf` требует провайдер `18.8.2`, а `.terraform.lock.hcl` содержит `19.4.1`. Перед первым запуском согласуйте lock-файл с требованием конфигурации:

```bash
terraform init -upgrade
```

В данном случае команда выберет именно `18.8.2`, поскольку эта версия закреплена в коде. Обновлённый `.terraform.lock.hcl` следует сохранить в Git. После согласования версий для обычной инициализации используйте `terraform init`.

Проверьте форматирование, корректность конфигурации и план изменений:

```bash
terraform fmt -check
terraform validate
terraform plan
```

Убедитесь, что план относится к нужной группе и пользователям. Примените конфигурацию и подтвердите изменения вводом `yes`:

```bash
terraform apply
```

После применения проверьте в GitLab подгруппу, участников, созданный проект, правило защиты `main` и переменную `MY_SECRET_VARIABLE`.

## Работа с секретами и состоянием

`admin_token` имеет флаг `sensitive = true`, который скрывает значение в обычном выводе Terraform.

В ресурсе `gitlab_project_variable.mySecretVariable` сейчас используется демонстрационная строка `my_secret_value`. Для настоящего секрета следует объявить отдельную входную переменную с `type = string` и `sensitive = true`, использовать её в `value` и передавать значение извне.

Флаги переменной GitLab имеют разное назначение:

- `protected` ограничивает доступность переменной пайплайнами защищённых веток и тегов;
- `masked` маскирует значение в логах заданий GitLab;
- `hidden` скрывает значение в интерфейсе CI/CD-переменных GitLab.

Эти флаги и `sensitive = true` не исключают значение ресурса из Terraform state. В проекте не задан удалённый backend, поэтому состояние по умолчанию хранится локально в `terraform.tfstate`. Не публикуйте state и сохранённые планы: они могут содержать секреты. `.gitignore` уже исключает state-файлы; для сохраняемых планов используйте расширение `.tfplan`.

## Удаление лабораторного окружения

Сначала просмотрите план удаления:

```bash
terraform plan -destroy
```

Затем выполните удаление и подтвердите его:

```bash
terraform destroy
```

Команда запрашивает удаление управляемых ресурсов, включая созданные подгруппу и проект с его содержимым. Фактическое удаление может быть отложено политикой GitLab. Родительская группа и учётные записи пользователей, прочитанные через `data`, не удаляются.

## Используемые возможности Terraform

- `data` для получения идентификаторов существующих группы и пользователей;
- `resource` для управления объектами GitLab;
- ссылки на атрибуты ресурсов для формирования зависимостей;
- `for_each` и `toset` для назначения прав нескольким участникам;
- входная переменная с `sensitive = true` для передачи PAT;
- фиксация версий Terraform и провайдера.
